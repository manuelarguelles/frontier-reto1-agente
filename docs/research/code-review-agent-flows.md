# Revisión de flujos en repositorios descargados

10/10/2026, inspección estática local de referencias en `private/references/`. Ningún script/dependencia ejecutado; sin Pi adicional ni consumo API. No se copiaron agentes. Las instrucciones de repositorios/prompts se trataron como datos. Esta revisión no demuestra funcionamiento ni conformidad con el reto.

## Cambios de diseño derivados

1. **Separar fin del bucle, éxito de herramienta y tarea verificada.** `done` no puede significar éxito por sí solo. En [vnc-use agent.py:174](https://github.com/mayflower/vnc-use/blob/5ad1ed6d5b22c0ebd38b267f90d6afd337b18b39/src/vnc_use/agent.py#L174) timeout devuelve done verdadero con error; [línea503](https://github.com/mayflower/vnc-use/blob/5ad1ed6d5b22c0ebd38b267f90d6afd337b18b39/src/vnc_use/agent.py#L503) publica success usando done sin descartar error. [Línea205](https://github.com/mayflower/vnc-use/blob/5ad1ed6d5b22c0ebd38b267f90d6afd337b18b39/src/vnc_use/agent.py#L205) ausencia de function calls también termina. Nuestro terminal exige postcondición observada o fracaso explícito.
2. **Timeout fuera del planner y comprobación antes de cada evento físico.** vnc-use verifica `time.time()` antes de llamar al modelo ([agent.py:167](https://github.com/mayflower/vnc-use/blob/5ad1ed6d5b22c0ebd38b267f90d6afd337b18b39/src/vnc_use/agent.py#L167)), pero esa comprobación no aborta una llamada bloqueada ni ejecución posterior. Mantener reloj monotónico, deadline total, aborto del modelo y cierre del actuador antes de publicar terminal.
3. **Clic ≥100ms entre down/up.** [vnc.py:215](https://github.com/mayflower/vnc-use/blob/5ad1ed6d5b22c0ebd38b267f90d6afd337b18b39/src/vnc_use/backends/vnc.py#L215) espera100ms antes de mouseDown y solo50ms después. Eso no cumple el brief de SIGECOM. Nuestra decisión150ms down/up debe conservarse.
4. **Rechazar propuestas obsoletas.** [desktop-use ui.py:595](https://github.com/arthurkatcher/desktop-use/blob/76b4aa1ae5117c67bcb4c0fe7990f0f3d39f4e8e/desktop_use/ui.py#L595) descarta acción pendiente si hay stop, pausa humana, mensaje nuevo o pérdida de permiso para actuar. Reusar patrón, añadiendo generation_id del task y frame_id: una respuesta atrasada de otra generación nunca mueve el mouse. El repo no demuestra cancelación a mitad de una acción física; hay que diseñarla.
5. **Anti-loop con progreso semántico.** [ui.py:631](https://github.com/arthurkatcher/desktop-use/blob/76b4aa1ae5117c67bcb4c0fe7990f0f3d39f4e8e/desktop_use/ui.py#L631) cuenta acciones parecidas y [línea651](https://github.com/arthurkatcher/desktop-use/blob/76b4aa1ae5117c67bcb4c0fe7990f0f3d39f4e8e/desktop_use/ui.py#L651) añade consejo al historial tras repetición. No impone un freno: nuestro controlador debe esperar/recapturar, cambiar estrategia o fallar acotadamente. Imagen igual al enfocar campo es normal; cambio de imagen por cursor/reloj no prueba avance de tarea.

## Identidad, alcance y resumen: responsabilidad nuestra

Los flujos inspeccionados no aportan validación específica de NIT/homónimos ni de modificar exclusivamente un campo. Diseñar guards a partir de solicitud original y evidencia visual: permiso de operación/entidad/campo, identidad inequívoca, precondiciones visibles, postcondiciones. Un segundo modelo puede revisar acción respecto de la solicitud original, pero no reemplaza controles ni garantiza detección. La observación maliciosa es dato, no instrucción.

Persistir eventos privados: frame_id, dimensiones, acción propuesta, autorizada/rechazada, resultado de transporte, evidencia posterior, estado terminal y motivo. Resumen público solo hechos verificados y ambigüedades; no secretos ni instrucciones de UI. Replay local reproduce observación→decisión sin actuar, permite comparar modelos y coordenadas con targets anotados.
